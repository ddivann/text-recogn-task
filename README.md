# Локальное распознавание чеков

Небольшая консольная программа на Python. Вся логика находится в `receipt_reader.py`:
чтение документа, разбор строк, проверка сумм, вывод в консоль и JSON.
Нет серверов, базы данных и облачных API. Чеки никуда не отправляются.

## Установка

Нужен Python 3.10 или новее. Проверено на Windows с Python 3.12 и Tesseract 5.5.0.

```powershell
py -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
```

Для фотографий, сканов и режима `--ocr` установите
[Tesseract 5.5.0 для Windows](https://github.com/tesseract-ocr/tesseract/releases/tag/5.5.0).
Стандартный путь `C:\Program Files\Tesseract-OCR\tesseract.exe` определяется автоматически.
Если Tesseract установлен в другом месте, добавьте его в PATH или задайте переменную:

```powershell
$env:TESSERACT_CMD = 'D:\Tesseract-OCR\tesseract.exe'
```

Папка `tessdata` рядом с программой уже содержит русскую и английскую модели.
Не удаляйте её при переносе проекта. Установка зависимостей требует интернета;
после установки обработка работает офлайн, программа ничего не скачивает.
Для PDF с текстовым слоем Tesseract не нужен.

## Запуск

Обработать два приложения и сохранить JSON:

```powershell
.venv\Scripts\python.exe receipt_reader.py "Приложение к заданию 1.pdf" "Приложение к заданию 2.pdf" --output results/results.json
```

Проверить именно распознавание изображений, игнорируя текстовый слой PDF:

```powershell
.venv\Scripts\python.exe receipt_reader.py "Приложение к заданию 1.pdf" "Приложение к заданию 2.pdf" --ocr --output results/results_ocr.json
```

Фотографии PNG/JPG обрабатываются тем же способом:

```powershell
.venv\Scripts\python.exe receipt_reader.py photo.jpg --output results/photo.json
```

Один файл должен содержать один документ; у PDF может быть несколько страниц.
По умолчанию программа читает текст каждой страницы, а при его отсутствии запускает OCR.
Режим `--ocr` всегда запускает Tesseract. Изображение PDF создаётся локально с масштабом 3.

## Результат

В консоли отображаются товары, количество, цена, сумма, доставка, итог и реквизиты.
JSON содержит массив результатов по файлам. Основные поля:

| Поле | Значение |
| --- | --- |
| `document_type` | `receipt`, `bank_operation` или `unknown` |
| `items` | Товары: `name`, `quantity`, `unit`, `unit_price`, `amount` |
| `delivery` | Общая стоимость найденных позиций доставки; отдельно от товаров |
| `total` | Итог кассового чека |
| `operation_amount` | Положительная величина списания по банковской операции |
| `date`, `time`, `merchant` | Дата, время и продавец |
| `payments`, `details` | Способы оплаты и доступные реквизиты |
| `checks`, `warnings` | Проверки сумм и замечания |
| `method`, `raw_text` | Способ чтения и исходный извлечённый текст |

Деньги записаны строками с двумя знаками после точки, вычисления выполняются через `Decimal`.
Это сохраняет точность. Идентификаторы также остаются строками, чтобы не потерять ведущие нули.
`null` означает, что значение не найдено; отсутствие доставки не заменяется нулём.
Ошибки открытия файлов записываются в JSON, остальные файлы продолжают обрабатываться.
Код завершения 1 означает ошибку обработки файла; замечания о качестве остаются в `warnings`.

## Что получилось на приложениях

- Приложение 1: 7 товаров на 6 739,00 руб., доставка 439,00 руб., итог 7 178,00 руб.
  Безналичными 6 878,00 руб., встречным предоставлением 300,00 руб. Обе проверки сумм проходят.
- Приложение 2: банковская операция на 6 878,00 руб. от 04.04.2026, 23:31,
  статус «Выполняется». Товаров и доставки в документе нет. Итог кассового чека не подставляется.

Оба PDF имеют текстовый слой. Обычный режим сохраняет названия из этого слоя.
При принудительном OCR суммы также верны, но есть ошибки в символах:
`PWK` распознаётся как `РИК`, `ОСН` — как латинское `OCH`, а `x` — как кириллическое `х`.
Эти значения не исправляются вручную и не скрываются в отчёте.
Совпадение суммы банковской операции с безналичной частью чека само по себе не доказывает,
что документы относятся к одной покупке.

## Ограничения

Это решение тестового задания, а не универсальный сервис для любых чеков.
Разбор рассчитан на структуру приложений и похожие строки с номером позиции,
названием, ценой, количеством, единицей измерения и суммой. Сильно иной макет,
повреждённое изображение, поворот страницы или нечитаемый шрифт могут потребовать адаптации.
Проверка суммы помогает обнаружить ошибки, но не гарантирует правильность всех названий и реквизитов.
Для банковского формата поддержано списание с отрицательным знаком и указанием рублей.

## Проверки

```powershell
.venv\Scripts\python.exe -m unittest -v
```

Проверяются исходные приложения, переносы названий, суммы, дробные цены,
отсутствующие данные, неверная дата, изменённый итог и продолжение после ошибки файла.
